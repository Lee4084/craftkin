Craftkin：iOS 17.6 降至 iOS 15.6 的兼容性评估
实施进度更新：用户已授权并完成兼容代码改造，当前结果见同目录 IMPLEMENTATION.txt。下文保留的是改动前评估。
日期：2026-11-19
状态：仅讨论和评估，尚未实施。没有修改 App 源码、工程最低版本或 Cloudflare 部署。

结论
可通过系统框架兼容改造支持 iOS 15.6，属于中等范围。初步影响 18 个现有 Swift 文件、1 个 Xcode 工程文件，预计另需 2 至 4 个兼容封装文件，具体数量取决于封装方式和后续编译结果。
主要工作量在媒体选择/导入与卡片呈现；其余多为状态管理和界面 API 的替换。
目前不能只把 Deployment Target 改为 15.6：已临时指定该版本进行编译探测，实际编译失败。

当前配置和依据
- 57 个 Swift 源文件，App target Debug/Release 都为 17.6；project 层 Debug/Release 仍为 26.4。
- 正式实施时需要将同一 project.pbxproj 内四处最低版本统一为 15.6，避免 target 继承变化后反弹。
- 使用系统框架，未发现 Swift Package、Pods 或其它原生第三方依赖的最低系统版本阻挡。
- 用当前 Xcode / iPhoneOS26.4 SDK 编译。命令行覆盖 IPHONEOS_DEPLOYMENT_TARGET=15.6，没有编辑工程文件。
- 探测日志在 /tmp/craftkin-ios156-compatibility-audit.log，退出码 65，BUILD FAILED。
- 首轮明确错误：PhotosPickerItem/TransferRepresentation 和部分 Font.system 重载要求 iOS 16；Observable/Observation 宏要求 iOS 17。编译在模块生成阶段失败，不代表日志已列出所有问题。
- 进一步以本机 Apple SDK 的 swiftinterface/头文件验证 API 可用性，并扫描所有 App Swift 文件。

一、必须处理的范围

1. 网页交互单例的状态管理（iOS 17 API）
文件：Legal/LegalConsentHandler.swift、Legal/LegalConsentView.swift、Legal/presentPrivacyAndTerms.swift。
目前：单例为 @Observable，两个显示页面用 @State 持有它；存在 10 个 ObservationIgnored 属性。
方案：使用 ObservableObject；只对 pages、notice 使用 @Published，视图使用 @ObservedObject 订阅单例；移除 Observation 宏及其忽略标记。
结果：打开/关闭网页、关闭按钮、客服、Token 同步、手势和保持唤醒等交互逻辑与消息名保持原样。需要验证数组内页面变化能正确刷新界面。

2. 导航容器（iOS 16 API）
共 6 处 NavigationStack，分布在 CaptureRootView、DataSupportViews、ProfileEditView、LibraryDetailViews、presentPrivacyAndTerms、OnboardingRootView。
未发现 NavigationPath 或基于值的 navigationDestination 路由链，替换难度相对有限。
方案：兼容导航封装，iOS 15 使用单列 NavigationView；可让高版本继续使用 NavigationStack，或统一使用旧容器。
结果：原流程可保留；需检查返回、标题栏、模态页面导航和横屏布局。

3. 系统照片/视频选择及导入（iOS 16 API）
共 3 个入口：CaptureStartViews.swift 的视频导入、ProfileEditView.swift 的头像、Integration/MediaViews.swift 的练习照片/视频。
使用 PhotosPicker、PhotosPickerItem、CoreTransferable、FileRepresentation、loadTransferable，不能仅给点击处添加 #available 后继续在低版本类型属性中引用它们。
方案：封装 PHPickerViewController，通过 NSItemProvider 取图片/视频，保留当前 LocalVideoImporter、LocalMediaStore、ProfilePhotoProcessor 的校验及存储流程。
结果：保留照片、视频、头像选择功能，无需整库读取权限。
重点：视频临时 URL 要在 provider 回调有效期内复制；处理 iCloud 资源等待、取消、失败、时长/大小限制和临时文件回收。
ImportedVideo 可调整为普通传输结果类型，不再要求 Transferable。

4. 卡片呈现和导航栏背景（iOS 16 API）
4 处 presentationDetents、3 处 presentationDragIndicator，分布于 LegalConsentView、LibraryBrowseViews、OnboardingRootView；另有 presentPrivacyAndTerms 的 toolbarBackground。
方案：iOS 15 使用 UISheetPresentationController，导航栏背景按当前容器设置 UINavigationBarAppearance；可将兼容代码集中在一个封装中。
结果：用户要求的 large 大屏卡片、隐藏拖动条、禁止下拉关闭、右上角 Close 均可以保留；不是必须退回全屏。
UIKit 的 medium/large detents 从 iOS 15 提供；isModalInPresentation 从 iOS 13 提供。
重点：保持原有 sheet 状态回写、显式关闭、窗口关闭和重复 present 时的生命周期正确。

5. 状态变化回调（iOS 17 新重载）
两参数 onChange 共 9 处、5 个文件：CaptureStartViews、FamilySpaceSetupViews、LibraryRootView、MediaViews、LegalConsentView。
方案：使用低版本单个 newValue 参数的 onChange；不需要参数的回调忽略 newValue。
结果：搜索/输入校验、导入触发、媒体跳转、App 前后台处理等行为保持。

6. 分享（iOS 16 API）
DataSupportViews.swift：1 处 ShareLink。
方案：UIActivityViewController 包装，继续传入已生成的导出文件 URL。
结果：保留保存/分享导出文件，检查取消和完成后的临时文件生命周期。

7. 界面小 API
- ContentUnavailableView：2 处，MediaViews、LibraryBrowseViews。使用现有图标/文字组合成兼容空状态组件，功能不变。
- ViewThatFits：1 处，LibraryDetailViews 的 MakerProfileView。iOS 15 使用竖排或按尺寸调整的兼容布局；小屏与大字效果需要验收。
- Font.system(TextStyle, design:, weight:)：25 处、9 文件。改用 .system(style, design:).weight(weight)，保留动态字体和字体设计，不改成固定字号。
- lineLimit 范围/预留行数：4 处、3 文件。旧版使用可用的行数限制和最小高度，必要时按版本保留高版本效果。
- scrollIndicators：5 处、4 文件。改为 ScrollView 的 showsIndicators 参数。
- scrollDismissesKeyboard：2 处、2 文件。iOS 15 可用兼容滚动封装设置 keyboardDismissMode，或接受较小的键盘收起体验差异。

二、不应误判为必改项
- 当前 SDK 的 autocorrectionDisabled 已通过 alwaysEmitIntoClient 支持 iOS 13，不应只凭名字认定为 iOS 16 限制。
- 当前 SDK 的 topBarTrailing 标注 iOS 14，并 backDeployed 到 iOS 17 之前，不是本轮确定的编译阻挡。
- Task/async-await、Swift 默认 MainActor、nonisolated 等不能简单等同于 iOS 17 要求；编译器版本和最低运行系统是两件事。
- 当前 WKScriptMessageHandlerWithReply、callAsyncJavaScript 等主要桥接 API 从 iOS 14 提供，可以保留。
- Keychain/UserDefaults/JSON 数据格式、固定 /start URL、协议同意记录和 JS 指令名称不需要因最低版本变更而更换。

四、网页部分
当前 Cloudflare 静态 HTML/CSS/consent.js 暂未发现必须因 iOS 15.6 而重写的点，固定入口与部署目录不需要改变。
保留活动代码里的 findLast、randomUUID 和 CSS 动态视口单位需结合 WebKit 15.x 验证；WebKit 15.4 已支持上述 findLast/动态视口等主要特性，不能直接归类为 iOS 16/17 独有。
仍需在 iOS 15.6 实际检查协议底部按钮、安全区、横屏、音视频自动播放、第三方网页与回调。筹备中的远程活动页面代码不在当前静态协议包中，不能替它保证全部兼容。

五、预期结果和验收边界
目标：App 可在 iOS 15.6 及以上安装运行，现有主要功能保留；高版本可保持现有界面，旧版本通过系统兼容封装实现相近效果。
主要视觉差异可能发生在导航标题、卡片动画、空状态默认样式、文字预留高度和键盘收起方式，可通过少量定制缩小。
功能风险集中在大视频/iCloud 导入、模态卡片关闭和前后台切换；旧设备内存及 SF Symbols 图标可用性需补充运行验收。
现阶段只有审计与失败编译证据，不是已适配完成；没有在 iOS 15.6 真机或模拟器运行。
实施后需 Debug/Release 均编译，再由用户指定设备实测：协议同意/重启、原生导航、三处媒体导入、拍摄、视频播放、导出分享、第三方卡片和原有数据恢复。

六、建议的实施方式（待讨论，不执行）
1. 以系统框架封装照片选择、分享、卡片和少量界面兼容逻辑，统一处理，避免页面里散落大量版本判断。
2. 替换 Observation、旧版 onChange 和字体等确定的编译阻挡。
3. 处理导航与卡片，保留 large/禁止下拉/Close 要求。
4. 实施完成时统一工程最低版本为 15.6，再按编译器继续补查次级问题。
5. 做原有流程回归和 iOS 15.6 运行验收；不要仅靠编译成功宣称已适配。
